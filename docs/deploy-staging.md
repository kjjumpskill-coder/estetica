# Тестовий майданчик: як підняти

Мета — живе посилання, яке можна дати Ользі на узгодження, не роблячи публічними
фото клієнток. Робиться один раз, далі кожна викладка — це `./deploy.sh`.

---

## 1. Піддомен на хостингу

У панелі ukraine.com.ua створіть піддомен, наприклад `test.<домен>` або
`estetika-test.<ваш-акаунт>`. Запам'ятайте **абсолютний шлях до його кореня** —
щось на кшталт `/home/<логін>/test.example.com`.

Важливо: корінь сайту має вказувати на `public_html` **всередині** цієї теки,
а не на саму теку. Тобто document root = `<шлях>/public_html`. Так `app/`,
`storage/` і `.env` лишаються поза вебом.

## 2. SSH-ключ

Публічний ключ уже є: `~/.ssh/id_ed25519.pub`. Додайте його в панелі хостингу
в розділі SSH-доступу.

Перед деплоєм завантажте ключ в агент, щоб `rsync` не питав пароль на кожному файлі:

```bash
ssh-add ~/.ssh/id_ed25519
```

Перевірка, що доступ працює:

```bash
ssh <логін>@<хост> "pwd && php -v"
```

## 3. База даних

Створіть у панелі порожню базу й користувача до неї. Реквізити знадобляться
на кроці 5 — вводьте їх безпосередньо на сервері, не пересилайте в листуванні.

## 4. Локальний `.env`

Заповніть **лише блок деплою** — це не паролі, а адреса призначення:

```
DEPLOY_HOST=<хост>
DEPLOY_USER=<логін>
DEPLOY_PATH=/home/<логін>/test.example.com
DEPLOY_PORT=22
DEPLOY_ENV=staging
```

Решта локального `.env` лишається як є: вона описує Docker на вашій машині,
і на сервер не потрапляє — `.env` виключений із rsync навмисно.

## 5. Серверний `.env`

Сервер має власний `.env`, який ви створюєте один раз руками:

```bash
ssh <логін>@<хост>
cd /home/<логін>/test.example.com
cp .env.example .env
nano .env
```

Що заповнити:

```
APP_ENV=staging
APP_DEBUG=false
APP_URL=https://test.example.com

DB_HOST=localhost
DB_NAME=<база>
DB_USER=<користувач>
DB_PASS=<пароль>

STAGING_USER=estetika
STAGING_PASS=<придумайте пароль для показу>

ANALYTICS_SALT=<довгий випадковий рядок>
```

`STAGING_PASS` — це той пароль, який ви даєте Ользі разом із посиланням.
Поки він заданий, сторінки, фото й асети закриті.

Згенерувати сіль:

```bash
openssl rand -hex 32
```

## 6. Перша викладка

Спершу подивіться, що саме поїде, нічого не змінюючи:

```bash
./deploy.sh --dry-run
```

Потім по-справжньому:

```bash
./deploy.sh
```

Скрипт передасть код, поставить маркер `.staging` і нагадає про наступні кроки.

## 7. База й медіа на сервері

Міграції:

```bash
ssh <логін>@<хост> "cd /home/<логін>/test.example.com && php bin/migrate.php"
```

Медіа передається окремою командою — воно велике й змінюється значно рідше
за код, тому не має їхати з кожним деплоєм:

```bash
rsync -avz -e "ssh -p 22" public_html/media/ <логін>@<хост>:/home/<логін>/test.example.com/public_html/media/
```

## 8. Перевірка, що майданчик справді закритий

```bash
curl -sI https://test.example.com/            # має бути 401
curl -s  https://test.example.com/robots.txt  # має бути Disallow: /
```

І окремо — що фото не відкривається за прямим посиланням без пароля:

```bash
curl -sI https://test.example.com/media/works/<будь-який>-960.webp   # має бути 401
```

Якщо десь замість 401 приходить 200 — зупиніться й напишіть мені. Це означає,
що `mod_rewrite` на хостингу поводиться інакше, і статику треба закривати
засобами Apache.

---

## Коли переходимо на бойовий домен

У локальному `.env` міняєте `DEPLOY_ENV=production`, на сервері — `APP_ENV=production`
і `CACHE_TTL=3600`. Скрипт сам прибере маркер `.staging`, і статика знову
віддаватиметься веб-сервером напряму, а головна почне кешуватися в статичний HTML.
